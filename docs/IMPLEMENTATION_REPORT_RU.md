# Отчёт о реализации

Дата проверки: 9 октября 2026. Машина: Windows 10, Python 3.12.2.

## Что сделано

Исходный репозиторий сохранён без правок в `FPV-Vehicle-Tracking`. Рабочая копия — `UAV-Vision-Detection-Tracking`.

Окно PySide6, тёмная тема, русский и английский. Разделы: видео и RTSP, детекция БПЛА, автомобили, список целей, сопровождение, модель и обучение, производительность, запись, экспорт событий, настройки.

Режим БПЛА подключает Ultralytics YOLOv8 к локальному `.pt` или `.onnx`. Устройство: AUTO, CUDA или CPU; при недоступной или упавшей CUDA расчёт переходит на CPU. В результат попадают только известные классы: drone, quadcopter, FPV drone, fixed-wing UAV, bird, aircraft, car. Файл COCO вроде `yolov8n.pt` подписывается как общая модель, а не как детектор БПЛА.

Режим автомобилей оставлен на YOLOv4-tiny: выбор цели мышью, автовыбор, Original и Enhanced, виртуальные команды только на экран и в CSV.

Для БПЛА добавлены ByteTrack и BoT-SORT. BoT-SORT здесь — Калман и IoU, без ReID. Track ID держится на коротком пропуске. Состояния: DETECTED, TRACKING, OCCLUDED, LOST, REACQUIRED. Скорость показывается в пикселях в секунду. км/ч — только если заданы метры на пиксель.

События для Command Center пишутся в JSONL и уходят UDP. В них нет широты, долготы и дальности. PTZ по умолчанию виртуальный, с пределами и безопасным стопом.

Обучение: импорт изображений, видео и разметки YOLO, разбиение train/val, запуск Ultralytics из локального `.pt`, чтение метрик из `results.csv`. Пустые метрики не заменяются выдуманными процентами.

Демо-режим явно помечен DEMO / SIMULATED DATA. Синтетические детекции не выдаются за выход сети.

## Зависимости, которые реально стоят в `.venv`

- opencv-python 4.14.0.94
- numpy 2.5.3
- PySide6 6.12.0
- ultralytics 8.4.174
- torch 2.14.1+cpu

`torch.cuda.is_available()` на этой машине вернул `False`. Колёсо PyTorch собрано под CPU. Штатный `opencv-python` тоже не содержит CUDA DNN, поэтому автомобильный YOLOv4 на GPU здесь не заработает, даже если появится видеокарта: для него нужна отдельная сборка OpenCV с CUDA. Код перехода YOLOv8 с CUDA на CPU проверен подставным сбоем, не на настоящей видеокарте.

## Проверка исходной программы до правок

До изменений в копии прогнаны модульные проверки оригинала (фильтр, виртуальные команды, Original, Enhanced, эвристика скорости). Они прошли.

Загрузка детектора оригинала не прошла:

`ModelError: Missing model file(s): custom-yolov4-tiny-detector_best.weights, custom-yolov4-tiny-detector.cfg`

В публичном репозитории нет весов, cfg и примеров кадров. Полный `tools/self_test.py` и `tools/gui_smoke.py` оригинала из-за этого не доходят до живого детектирования. До создания venv в системном Python не было OpenCV.

## Проверки новой версии

`python -m unittest tests.test_spec -v` — 16 тестов, все прошли.

| Проверка | Результат |
| --- | --- |
| Нет файла весов | ошибка, без скачивания |
| Свои классы drone/bird | person отброшен |
| Имена COCO | подпись «не модель БПЛА», person отброшен, airplane стал aircraft |
| Запрос CUDA при отсутствии CUDA и сбой predict | устройство становится CPU |
| Открытие видеофайла | кадр читается |
| Пустой RTSP и неоткрытый поток | `ConnectionError`, окно не роняется |
| Track ID через пропуск | тот же id, затем OCCLUDED и REACQUIRED |
| км/ч без калибровки | значение пустое; с метрами на пиксель — считается |
| JSON | есть sensor id, track id, UTC, класс, confidence, нормированная рамка, источник, статус; lat/lon отвергаются |
| UDP и JSONL | датаграмма принята локальным сокетом |
| train/val | 4 изображения разложены, классы взяты из `classes.txt` |
| Метрики | прочитаны из тестового `results.csv`; без файла результат пустой |
| Прогон видео без разметки | только количества, без процентов |
| Виртуальный PTZ | угол не выходит за пределы, стоп замораживает его |
| Демо-контур | на кадре есть баннер DEMO, у нескольких объектов разные id |

Окно запущено, открыты четыре демо-ролика, снимки сохранены в `demo/screenshots/`. Ролики по 20 секунд, 1280×720, 25 кадр/с, лежат в `demo/video/`.

Живая RTSP-камера в сети не проверялась. Обучение на реальном наборе БПЛА не запускалось, поэтому precision, recall и mAP не приводятся. Полноценный Command Center из публичного репозитория в момент просмотра содержал только описание формата и заготовку файла, без тела приёмника; адаптер сверен с этим описанием и проверен локальным UDP.

## Что не работает без дополнительных данных

- Детекция БПЛА настоящей сетью — пока в интерфейсе не указан свой файл весов с нужными классами.
- Детекция автомобилей YOLOv4-tiny — пока в `model/` нет weights и cfg.
- км/ч, GPS и дальность — не вычисляются из пикселей.
- Реальный стабилизированный подвес — есть только виртуальный адаптер.
- Внешний вид объекта в BoT-SORT — ReID нет.
- CUDA на этой машине — пакет CPU, запасной путь на CPU срабатывает.

## Как запустить

```bat
cd UAV-Vision-Detection-Tracking
install.bat
start.bat
```

Демо без весов: вкладка «Детекция БПЛА», кнопка «Открыть демо-запись».
