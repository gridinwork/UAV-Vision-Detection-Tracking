# Руководство

## Назначение

Программа обнаруживает объекты на кадре, ведёт треки и может передать событие в Command Center. Режим **БПЛА** использует YOLOv8 (файл `.pt` или `.onnx`). Режим **автомобилей** использует прежний YOLOv4-tiny.

Виртуальные команды автомобиля остаются на экране и в CSV. Виртуальный PTZ только меняет внутренние углы. На борт и на средства воздействия ничего не отправляется.

## Установка

```bat
install.bat
start.bat
```

`install.bat` создаёт `.venv`, ставит OpenCV 4, NumPy и PySide6, затем пытается поставить `ultralytics`. Если пакет YOLOv8 не установился, демо-режим, запись и автомобильный трекер всё равно запускаются. Загрузка своих весов `.pt` / `.onnx` в этом случае недоступна.

Проверка импортов:

```bat
.venv\Scripts\python.exe tools\verify_install.py
.venv\Scripts\python.exe -m unittest tests.test_spec -v
```

## Веса

### Автомобили

В каталог `model/` нужно положить файлы, которые публичный репозиторий не распространяет:

- `custom-yolov4-tiny-detector_best.weights`
- `custom-yolov4-tiny-detector.cfg`
- `classes.txt` (в поставке уже есть класс `car`)

### БПЛА

Укажите в интерфейсе свой файл `.pt` или `.onnx`. При запуске приложение ничего не скачивает. Кнопка «Скачать все веса и нейросети» на вкладках «Детекция БПЛА» и «Модель и обучение» проверяет ссылки из `model/catalog.json` и складывает прошедшие проверку файлы в базу `model/library/weights.sqlite`, а сами файлы — в `model/library/files`. Страница вместо файла отбрасывается. Веса COCO в каталоге нет. Если в базе есть пригодная модель БПЛА, её путь подставляется в поле весов.

Классы попадают в результат только если имя в модели совпадает с одним из: `drone`, `quadcopter`, `FPV drone`, `fixed-wing UAV`, `bird`, `aircraft` (`airplane` отображается как aircraft), `car`.

Файл вроде `yolov8n.pt` — это общие веса COCO. В интерфейсе он так и подписан: это не модель обнаружения БПЛА. Класса drone в COCO нет.

Настройки детектора: порог confidence, NMS IoU, устройство AUTO / CUDA / CPU, размер входа 320–1280. AUTO и CUDA берут видеокарту NVIDIA, на которой больше свободной памяти и которая реально выполняет ядро PyTorch. Сборка torch 2.14.1+cu130 умеет считать на RTX 3060. GTX 1060 (архитектура Pascal, возможность 6.1) эта сборка не поддерживает и пропускает. Если ядро не запускается, расчёт переходит на CPU. Детектор автомобилей YOLOv4 идёт через OpenCV и остаётся на CPU: штатный пакет opencv-python не содержит модуля CUDA.

## Источники

Вкладка **Видео / RTSP**: файл MP4/AVI/MOV/MKV, камера 0–2, адрес RTSP. Пустой адрес и неоткрытый поток дают сообщение об ошибке и не останавливают окно. Для файла есть пуск, пауза, стоп, перемотка, режим реального времени и режим каждого кадра.

## Сопровождение

Цель выбирается автоматически у центра, щелчком мыши или как первая устойчивая. Для БПЛА трекер — ByteTrack или BoT-SORT.

BoT-SORT в этой версии — фильтр Калмана и сопоставление по IoU. Отдельной модели внешнего вида (ReID) нет.

Короткий пропуск детекции сохраняет Track ID. Состояния: `DETECTED`, `TRACKING`, `OCCLUDED`, `LOST`, `REACQUIRED`.

На кадре рисуются рамка, класс, Track ID, confidence, статус и скорость. Подписи кадра, статусы и названия известных классов следуют языку из вкладки «Настройки». По умолчанию язык русский. В JSON для командного центра класс и статус остаются английскими кодами.

Скорость в пикселях в секунду есть всегда. Километры в час считаются только если в поле «метров на пиксель» введено значение больше нуля: пиксели в секунду × метров на пиксель × 3,6. Это коэффициент калибровки, его нужно измерить по сцене. Пока поле равно нулю, в интерфейсе написано «нет калибровки», а в JSON километры в час не подставляются.

## Демонстрация

Кнопка **Открыть демо-запись** строит или открывает синтетический ролик. На кадре и в заголовке есть надпись **DEMO / SIMULATED DATA**. Детекции в этом режиме взяты из сценария, а не из нейросети.

Готовые ролики и снимки окна лежат в `demo/`.

## Обучение

Вкладка **Модель и обучение**:

- импорт изображений, кадров из видео и файлов разметки YOLO;
- разбиение на train/val и `data.yaml`;
- запуск обучения или дообучения из локального `.pt`, если установлен ultralytics;
- чтение precision, recall, mAP50, mAP50-95 и картинки матрицы ошибок из папки реального прогона Ultralytics.

Если прогона не было, метрики остаются пустыми. Проценты не придумываются.

**Прогнать тестовое видео** считает детекции загруженной моделью. Точность по IoU считается только когда рядом есть файлы разметки. Сцены для проверки (малый объект, засветка, облака, промышленный фон, перекрытие, птицы) можно собрать кнопкой создания демонстрационных роликов; сами по себе они не являются измерением качества модели.

## Запись и экспорт

Запись обработанного видео — 15–30 секунд. Снимок кадра сохраняется в `screenshots/`. Полный ролик уходит в `output/`. CSV виртуального сопровождения — в `logs/control/`.

## Command Center и PTZ

Формат событий описан в [АДАПТЕР_COMMAND_CENTER.md](АДАПТЕР_COMMAND_CENTER.md).

PTZ по умолчанию виртуальный: пределы поворота, калибровочные смещения, ведение за целью и безопасный стоп (скорость обнуляется, угол удерживается).

## Журнал

`logs/app.log` — запуск, источник, смена цели и ошибки. Покадровый поток туда не пишется.
